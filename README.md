# IEMS - لوحة أداء الموظفين (Employee Performance Dashboard)

نظام كامل (Backend + قاعدة بيانات + واجهة) لعرض بيانات ملف Master بتاعك لكل موظف بعد تسجيل الدخول.

## المكونات
- **Backend:** Node.js + Express
- **قاعدة البيانات:** SQLite (ملف واحد محلي، بدون تنصيب سيرفر قاعدة بيانات منفصل)
- **المصادقة (Auth):** كلمات مرور مشفّرة (bcrypt) + جلسات JWT
- **الواجهة (Frontend):** صفحات HTML/CSS/JS بسيطة بتتواصل مع الـ API

## هيكل المشروع
```
backend/
  server.js              نقطة تشغيل السيرفر
  routes/auth.js          تسجيل الدخول + تغيير كلمة المرور
  routes/employee.js      بيانات الموظف + الفلاتر
  middleware/auth.js       التحقق من الـ JWT
  db/init.js               تعريف جداول قاعدة البيانات
  db/seed.js                تحميل بيانات الإكسيل + توليد كلمات مرور
  db/employees_source.json   البيانات المستخرجة من شيت Master
  public/                  صفحات تسجيل الدخول والداشبورد
```

## التشغيل محليًا (خطوة بخطوة)

### الطريقة السريعة (أمر واحد بس)
لو عندك Node.js متثبت خلاص، شغّل السكريبت ده وهيعمل كل حاجة لوحده (تثبيت المكتبات + إعداد .env + تشغيل السيرفر):

**على Mac / Linux:**
```bash
cd backend
bash setup.sh
```

**على Windows:**
دبل كليك على `setup.bat` (أو شغّله من الـ cmd/PowerShell جوه فولدر backend)

أول تشغيل هيولّد قاعدة البيانات وكلمات مرور الموظفين تلقائيًا، وهتلاقيها متطبعة في نفس نافذة الـ Terminal، وكمان محفوظة في `db/credentials_TO_DISTRIBUTE.csv`. بعد ما يشتغل، افتح المتصفح على http://localhost:3000

### الطريقة اليدوية (لو عايز تتحكم في كل خطوة)

### 1. تثبيت المتطلبات
```bash
cd backend
npm install
```

### 2. إعداد ملف البيئة
```bash
cp .env.example .env
```
افتح `.env` وحط قيمة عشوائية طويلة لـ `JWT_SECRET` (تقدر تولّدها بالأمر `openssl rand -hex 32`).

### 3. تجهيز قاعدة البيانات وكلمات المرور
```bash
npm run seed
```
هيعمل قاعدة بيانات جديدة، ويولّد **كلمة مرور عشوائية (٦ أرقام) لكل موظف**، ويكتبها في:
```
db/credentials_TO_DISTRIBUTE.csv
```
⚠️ **مهم جدًا:** الملف ده فيه كل كلمات المرور بالنص الصريح. وزّعه على الموظفين بطريقة آمنة (مثلاً كل موظف ياخد رقمه هو بس)، وامسحه بعد كده. يوجد أيضًا حساب مدير (Admin) بـ ID=0 يقدر يشوف كل الموظفين.

### 4. تشغيل السيرفر
```bash
npm start
```
هيفتح على: http://localhost:3000

افتح المتصفح على الرابط ده، وسجل دخول بأي ID وكلمة مرور من ملف الـ CSV.

## إعادة تحميل بيانات جديدة من إكسيل
لو عندك ملف Master محدث، شغّل نفس سكريبت الاستخراج (اللي استخدمناه في المحادثة) عشان تولّد `employees_source.json` جديد، حطه مكان الملف الحالي في `db/`، وبعدين شغّل:
```bash
npm run seed
```
⚠️ ده هيمسح قاعدة البيانات القديمة (وبالتالي كل كلمات المرور اللي اتغيرت) ويولّد كلمات مرور جديدة. لو عايز تحافظ على كلمات المرور الحالية، محتاج تعدّل `seed.js` يبقى "update" بدل "wipe & recreate" - قولّي لو عايز أعملها كده.

## الصلاحيات
- **موظف عادي:** يشوف بياناته هو بس (أي محاولة يشوف موظف تاني بترجع 403)
- **مدير (admin, ID=0):** يقدر يختار أي موظف من القائمة ويشوف بياناته

## الفلاتر المتاحة
- اختيار الموظف (للمدير فقط؛ الموظف العادي مقفول على نفسه)
- من تاريخ / الى تاريخ
- المرحلة (RE_FILE, CREATION, SCAN FUJITSU... الخ)

## النشر على الإنترنت (Deployment) — جاهز على Render

المشروع فيه `Dockerfile` و `render.yaml` جاهزين، فالنشر بيبقى بسيط:

### الخطوات على Render (render.com)
1. اعمل حساب على [render.com](https://render.com) وارفع الفولدر ده كـ Git repo (GitHub/GitLab)
2. من لوحة Render: **New → Blueprint**، واختار الـ repo — هيقرأ `render.yaml` تلقائي ويجهز كل حاجة:
   - يبني الـ Docker image
   - يولّد `JWT_SECRET` عشوائي وآمن تلقائيًا
   - يعمل قرص دائم (Persistent Disk) لقاعدة البيانات عشان البيانات متتمسحش مع كل تحديث
3. **مهم:** قبل أول تشغيل، من إعدادات الخدمة (Environment) حط قيمة لـ `ADMIN_PASSWORD` بنفسك (كلمة مرور تختارها للمدير)، وإلا هيتولد باسورد عشوائي للأدمن
4. اضغط Deploy، واستنى لحد ما يخلص البناء

### أول تشغيل = تعبئة تلقائية للبيانات
السيرفر معمول بحيث لو قاعدة البيانات فاضية، بيعمل seeding تلقائي أول ما يشتغل (مفيش داعي تدخل شل يدوي). **كلمات المرور المولّدة لكل موظف بتتطبع في الـ Logs بتاعة الخدمة** (تقدر تفتحها من لوحة Render → Logs)، خد نسخة منها ووزعها بأمان.

⚠️ لو عايز تعيد التعبئة (Re-seed) بعد كده يدويًا لازم وصول لـ Shell على الخدمة (متاح على أغلب خطط Render المدفوعة عن طريق **Shell tab** في لوحة الخدمة) وتشغّل:
```bash
npm run seed
```

### بدائل استضافة تانية
- **Railway**: نفس الفكرة، بيدعم Dockerfile مباشرة، وبيوفر persistent volume للـ SQLite
- **VPS عادي (DigitalOcean / Hetzner / إلخ)**: تقدر تستخدم نفس الـ Dockerfile، أو تشغل المشروع مباشرة بـ Node + PM2 خلف Nginx كـ reverse proxy مع شهادة SSL من Let's Encrypt

### نصائح أمان قبل النشر الفعلي
1. تأكد إن `.env` مش متضاف لأي Git repo عام (موجود في `.gitignore` بالفعل)
2. فعّل HTTPS (كل المنصات فوق بتوفره تلقائي)
3. لو عدد المستخدمين كبير جدًا أو محتاج وصول متزامن من أكتر من سيرفر، فكر في الانتقال من SQLite إلى PostgreSQL
4. اعمل نسخة احتياطية دورية (backup) لملف قاعدة البيانات (`db/iems.db`) — على Render مع الـ Persistent Disk البيانات بتفضل موجودة بين الـ deployments، لكن دي مش بديل عن backup حقيقي

## ملاحظة عن بيانات ناقصة
٢٩ موظف في الملف الأصلي كان الـ ID بتاعهم فاضي في شيت Master. اتحطلهم ID مؤقت (900000 + رقمهم بالتسلسل) عشان يقدروا يستخدموا النظام، ومكتوب ملاحظة بكده جنب اسمهم في ملف الـ credentials. يُفضّل تصحيح الـ ID الحقيقي بتاعهم من HR وتحديث البيانات.
